# Authentication System Architecture

## Overview
The Clinic API supports multiple authentication methods:
1. **Email + Password** login
2. **Email OTP** login (passwordless)
3. **WhatsApp OTP** login (via phone number)
4. **Social Login** (Google OAuth 2.0)
5. **Registration** with email OTP verification (+ optional WhatsApp OTP)

All flows ultimately generate a JWT token for authenticated sessions.

## Authentication Flow Diagram

```
┌─────────────────────────────────────────────────┐
│                  LOGIN FLOWS                      │
├─────────────────────────────────────────────────┤
│                                                   │
│  Email + Password ──→ POST /api/auth/login        │
│       ↓                                           │
│  Verify BCrypt hash → Generate JWT → Return token │
│                                                   │
│  Email OTP ──→ POST /api/auth/send-otp            │
│       ↓         (sends 6-digit code to email)     │
│  POST /api/auth/verify-otp → Generate JWT         │
│                                                   │
│  WhatsApp OTP ──→ POST /api/auth/request-otp      │
│       ↓             (sends code via WhatsApp)     │
│  POST /api/auth/verify-otp → Generate JWT         │
│                                                   │
│  Google OAuth ──→ POST /api/auth/social            │
│       ↓                                           │
│  Validate token with Google → Find/Create user    │
│  → Generate JWT → Return token                    │
│                                                   │
├─────────────────────────────────────────────────┤
│              REGISTRATION FLOW                    │
├─────────────────────────────────────────────────┤
│                                                   │
│  POST /api/auth/register-send-otp                 │
│       ↓                                           │
│  Check email not already registered               │
│  Send email OTP (+ WhatsApp OTP if phone given)   │
│       ↓                                           │
│  POST /api/auth/register                          │
│       ↓                                           │
│  Verify email OTP (+ WhatsApp OTP if applicable)  │
│  Create User + role-specific record (Doctor/      │
│  Patient) + Clinic associations                   │
│  → Return user data (NO token — redirects to      │
│     login page)                                   │
│                                                   │
└─────────────────────────────────────────────────┘
```

## JWT Token Structure

Generated by `JwtService.cs`. Claims include:

| Claim | Source |
|---|---|
| `NameIdentifier` | `user.Id` |
| `Email` | `user.Email` |
| `Name` | `user.Name` |
| `Role` | `user.Role` (lowercase) |
| `title` | `user.Title` |
| `clinicId` | `user.ClinicId` (if set) |
| `doctorId` | `user.DoctorId` (if doctor) |
| `patientId` | `user.PatientId` (if patient) |
| `clinicIds` | Multiple claims, one per clinic (if doctor) |

Token configuration:
- **Algorithm**: HMAC-SHA256
- **Expiry**: 24 hours (configurable via `Jwt:ExpiryHours`)
- **Issuer**: `ClinicApi`
- **Audience**: `ClinicApp`

## OTP Services

### Email OTP (`OtpService`)
- Registered as **Singleton** (in-memory store persists across requests)
- Uses `ConcurrentDictionary<string, (string Code, DateTime Expiry)>`
- 10-minute expiration
- Key: email lowercased

### WhatsApp OTP (`WhatsAppOtpService`)
- Registered as **Singleton** via `AddHttpClient` (gets its own `HttpClient`)
- Uses `ConcurrentDictionary` for both OTP storage and rate limiting
- 5-minute expiration (configurable)
- 60-second cooldown between requests per phone number
- Phone normalization: strips `+`, `-`, spaces; compares last 9 digits

## Registration Role Logic

When a user registers:

| Role | Actions |
|---|---|
| **Doctor** | Creates `Doctor` record → Creates `DoctorClinic` associations → Creates `User` with `DoctorId` link |
| **Patient** | Creates `Patient` record → Creates `User` with `PatientId` link |
| **Assistant** | Creates `User` with `DoctorId` (supervising doctor) and `ClinicId` |
| **Admin** | Creates `User` with `ClinicId` |

### Doctor Clinic Creation
If a doctor registers with a `ClinicName` but no `ClinicIds`:
1. A new `ClinicEntity` is created automatically
2. The doctor is set as `CreatorDoctorId` on the clinic
3. A `DoctorClinic` join record is created with `Status = "Accepted"`

## Social Login (Google) Flow

1. Frontend gets Google ID token via `@abacritt/angularx-social-login`
2. Sends token to `POST /api/auth/social`
3. Backend validates token with Google's API (`https://www.googleapis.com/oauth2/v3/tokeninfo`)
4. If user exists → login (generate JWT)
5. If user doesn't exist and no role specified → return `requiresRoleSelection: true`
6. If role specified → auto-register as Doctor or Patient → generate JWT

## Profile Management

### Endpoints
| Endpoint | Method | Auth | Description |
|---|---|---|---|
| `/api/auth/profile` | GET | ✅ JWT | Get current user profile |
| `/api/auth/profile` | PUT | ✅ JWT | Update profile (with OTP verification for email/phone changes) |
| `/api/auth/profile-send-otp` | POST | ✅ JWT | Send OTP for profile email/phone change |

### Security
- Changing email requires email OTP verification
- Changing phone number requires WhatsApp OTP verification
- Password can be updated directly (hashed with BCrypt)
